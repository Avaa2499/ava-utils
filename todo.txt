1. [8] Indexer goes stale silently after missed changes
   From the reviews. If the watcher or indexer is down while files change, nothing reconciles the index; the watcher journal only holds the last N changes.
   Fix: the watcher topic state carries a generation number and an overflow/gap flag; the indexer detects a gap on (re)subscribe and rescans only the watched roots, as a normal job.
   Done when: stop the indexer, change files under a watched root, start it, and the index is correct with no manual scan. Test covers journal overflow too.

2. [6] Hung requests count as quarantine strikes, and refusals never expire
   From the reviews. A request that hangs and gets the module killed by the watchdog gets a strike; three hangs refuse a valid request forever.
   Fix: record that a restart was caused by the watchdog (not a crash in the request) and do not strike for it; add an expiry (e.g. 24h) to refusals, still clearable by hand.
   Done when: tests show a watchdog kill adds no strike, and an expired refusal is allowed again.

Q1. The cycle ban and the GUI. A GUI that sets watch roots (call to the watcher) and shows live index changes (event from the indexer) makes gui -> watcher -> indexer -> gui, a three-module loop, which is banned with no exception possible. Options: (A) GUI polls the indexer with calls and never subscribes, (C) ban only loops made entirely of calls, since only those can deadlock, and allow loops containing an event, (F) split the GUI into a view module and a control module.
